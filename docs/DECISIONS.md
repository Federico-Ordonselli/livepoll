# Decisions log

Short entries for every choice that was not obvious from the spec.
Format: **Decision** · _Why_ · _Alternative discarded_.

## Tooling

1. **AdonisJS pinned to v6 (`@adonisjs/core@^6.18`), API scaffolded from the official `api-starter-kit` at its last v6 revision.** · npm `latest` is already v7, and the spec requires v6. The kit pins a coherent set of ecosystem versions (assembler 7, japa 4, vine 3, cors 2, limiter 2). · `create-adonisjs@latest`, which would scaffold v7.
2. **TypeScript `~5.8` everywhere.** · TS 7 (native port) is `latest`, but Adonis v6 tooling (ts-node-maintained, @adonisjs/tsconfig 1.x) and typescript-eslint target TS 5.x. · TS 7.
3. **ESLint 9 everywhere.** · `@adonisjs/eslint-config@2` targets ESLint 9. One major across the monorepo avoids plugin mismatches. · ESLint 10.
4. **`packages/shared` is compiled to `dist/` (tsc) and built in the root `postinstall`.** · Adonis runs through a ts-node ESM loader, which does not reliably transpile `.ts` reached through workspace symlinks. Shipping JS + `.d.ts` works the same way for Node, Vite and Vitest. · Pointing `exports` at `src/*.ts`.
5. **pnpm pinned to the local version (12.11.2) via `packageManager`; `allowBuilds` only whitelists `@swc/core`.** · pnpm ≥10 blocks dependency build scripts by default; swc needs its postinstall to fetch the native binary. · Allowing all build scripts.
6. **Mongoose 8.x, not 9.x.** · 8.x is mature and widely documented. 9.x brings no feature this app needs. · Mongoose 9.
7. **Codex CLI (0.171) and Ollama are available and used as the spec describes.** Codex reviewed the API (after phase 2) and the whole repo (phase 6), and wrote the Playwright specs against a harness I wrote. Ollama (`qwen2.5-coder:14b`) drafted the README project tree. That draft nested `config/`, `providers/` and `start/` inside `app/`, so it served only as a file checklist and the tree was rewritten by hand. Claude subagents built the web app in parallel with the API (with the contract fixed first in `packages/shared`) and did an independent full review.
8. **Validation: shared `LIMITS` constants feed both VineJS (API HTTP layer) and zod (web forms + Socket.io payloads).** · The two validators cannot share schema objects, but sharing the numbers keeps them aligned. A test asserts that both reject the same edge cases. · Using zod in the API too, which would bypass the Adonis-native VineJS the spec asks for.

## API core

9. **No MongoDB transactions: the unique index plus `$inc` ordering guarantees correctness; Mongo runs as a plain standalone.** · The `votes` collection is the source of truth (unique `(pollId, voterId)` index). Counters are derived and only changed with `$inc` _after_ the vote document is written, and `$inc` commutes, so parallel requests sum correctly in any order. Vote changes are a compare-and-swap on the vote document (`{_id, optionId: old}` → new), so only one of N parallel changes wins each swap; the rest re-read and retry (max 10, then 409 `CONFLICT`). The only inconsistency window is a failure between the two writes (process crash, or MongoDB becoming unreachable after the vote insert): the vote is stored but not counted. A recount job would repair it (see README "What I'd do next"). · Transactions on a single-node replica set: all 50 parallel votes `$inc` the _same_ poll document, so transactions would abort with WriteConflict and retry in a storm. That costs more and is harder to explain, for a guarantee only needed on crash.
10. **A vote that passed the "poll is open" check is counted even if the poll closes milliseconds later.** · I first sketched "delete the vote if the poll closed mid-request". Tracing it out, that compensation can itself drift when a concurrent vote change by the same voter touches the same vote document. Counters always equal the vote documents; strictness at the millisecond level isn't worth breaking that. · A conditional `$inc` with compensating deletes.
11. **Session = signed httpOnly cookie `lp_session` holding `{ uid, exp }`; no JWT, no server-side session store.** · Adonis signs cookies with APP_KEY, using the cookie name as purpose (so a `voter_id` value can't be replayed as a session). The signature carries no expiry, so `exp` lives inside the payload and is checked server-side. Logout clears the cookie. Limitation: a stolen cookie stays valid until `exp` (7 days); a `sessions` collection would allow revocation. · A JWT in localStorage (readable by XSS), `@adonisjs/session` (adds a store for little benefit here).
12. **CSRF protection = `SameSite=Lax` cookies + JSON-only body parser + an `Origin` allow-list check on every non-GET request.** · Lax stops cookies being _sent_ cross-site, but not being _set_: an HTML form could still POST credentials to `/login` (login CSRF), hence no form/multipart parsing and the Origin check (403 for foreign origins). Requests without `Origin` are non-browser clients, which cannot ride a victim's cookies. · Shield's CSRF tokens, which need `@adonisjs/session`. _(Tightened after the Codex review, see below.)_
13. **Security headers via a ~15-line middleware instead of `@adonisjs/shield`.** · Shield targets server-rendered apps with sessions; a JSON API needs only nosniff, frame-deny, a CSP of `default-src 'none'`, a referrer policy, CORP and HSTS in production. · Shield plus `@adonisjs/session`.
14. **Rate limits use `@adonisjs/limiter` with the memory store, per IP: 10/min on register+login, 60/min on vote (env-configurable). `TRUST_PROXY=true` behind nginx.** · Simple, and a single API instance needs no Redis. Without trusting the proxy, every client would share nginx's IP. · Redis store (only needed with more than one instance).
15. **Validation errors are 422 with `details: [{ field, message }]`.** · The web form maps them to inputs. Other 4xx framework errors (malformed JSON, 404 route) map to the same `{ error: { code, message } }` shape, and unknown errors become a generic 500. The handler never sends stack traces (`debug = false`).
16. **Closing an already-closed poll returns 200 with the poll (idempotent).** · Retrying a close is harmless. · 409.
17. **`GET /api/polls/:slug` and the vote route share a `voter` middleware that issues the `voter_id` cookie (UUID v4, signed, httpOnly, 1 year).** · A first-time visitor gets an identity before voting, so `myVote` works right away.
18. **Route params are constrained with `SLUG_PATTERN`**, so malformed slugs 404 at the router and never reach MongoDB. Mongoose `sanitizeFilter` is on as defence in depth against `$`-operator injection.
19. **Login always runs a hash verification, even for unknown emails**, so response time doesn't reveal which emails are registered.

## Real-time

20. **Socket.io is attached in a provider's `ready()` hook via `server.getNodeServer()`.** · In Adonis v6, `ready()` runs after the ignitor created the Node HTTP server, so it's the first point where the server exists. Tests start their HTTP server later through `testUtils.httpServer()`, so `tests/bootstrap.ts` attaches it explicitly. On shutdown only the sockets are disconnected; Adonis closes the HTTP server. · A preload file, which runs before the HTTP server exists.
21. **`poll:updated` broadcasts are coalesced per poll: one in-flight MongoDB read plus a dirty flag.** · Broadcasting each request's own `findOneAndUpdate` result can deliver snapshots out of order under concurrency (an older count arriving after a newer one). Sequential re-reads guarantee the last broadcast reflects the latest state, and bursts send fewer messages. · Emitting per request, or adding a version field to the poll.
22. **Presence = `io.in(room).fetchSockets().length`, so it counts sockets, not people.** Two tabs count as two viewers, which matches the spec ("count of sockets in room"). `fetchSockets` also works if a Redis adapter is added later. On disconnect, the rooms are captured in `disconnecting` and recounted on `disconnect`, once the socket has actually left.
23. **A socket can be in only one poll room at a time; joining a new poll leaves the previous one.** · It matches the UI (one active poll per tab) and stops one socket from joining thousands of rooms. · Unlimited rooms per socket.
24. **Join payloads are validated with the shared zod schema. Invalid or unknown slugs are silently ignored; there is no error event.** · The contract defines no error event, and the REST `GET` is what reports 404 to the UI.
25. **Single API instance.** With more than one instance, Socket.io would need the Redis adapter and the limiter the Redis store. Not needed at this scale.

## Frontend

26. **The socket layer is a plain Redux middleware built by `createSocketMiddleware(createSocket)`, not the listener middleware.** · The factory argument lets tests inject a fake socket, and the whole socket lifecycle sits in one ~90-line file. Components only dispatch `watchPoll` / `unwatchPoll`.
27. **The middleware connects lazily on the first `watchPoll` and joins rooms only while connected; the `connect` handler (re)joins the current room.** · Emitting while disconnected would sit in socket.io's send buffer and produce a duplicate join on connect.
28. **On *re*connect (not the first connect) the middleware refetches the poll over REST.** · `poll:state` brings counts back, but votes or a close may have been missed while offline, and `myVote` only comes from REST.
29. **The poll page refetches on mount (`refetchOnMountOrArgChange`).** · `watchPoll` resets the poll slice, and a cached query result wouldn't refill it.
30. **Logout calls `api.util.resetApiState()`.** · The previous user's polls and `myVote` must not survive in the cache.
31. **The auth slice ignores "rejected" actions with `meta.condition` (deduplicated RTK Query requests).** · Otherwise StrictMode's double `me` call would mark the user as anonymous.
32. **Voting uses a native radio group plus one Vote / Change vote button.** · Arrow keys, Tab and Enter work without custom key handling. Results are always visible, not only after voting, since watching them live is the point.
33. **Result bars are `role="img"` with a full label ("Go: 1 vote, 100% (your vote)") inside an `aria-live="polite"` region; the visual text row is `aria-hidden` so it isn't read twice.** The width animation is off under `prefers-reduced-motion`.
34. **Closing from the dashboard has no confirm dialog.** · Fewer moving parts, and native `confirm()` dialogs interfere with E2E tests. A real product would use an undo or an inline confirm.
35. **The test setup patches the global `Request` to resolve relative URLs.** · Node's `Request` rejects `/api/...`; the patch lets the app keep `baseUrl: '/api'` in tests.
36. **Same-origin in every environment**: the Vite dev/preview server and nginx (Docker) proxy `/api` and `/socket.io`, so cookies stay first-party and CORS is a second line of defence, not a requirement.
37. **Known limitation: a REST vote response can arrive _after_ a newer `poll:updated` broadcast and briefly show slightly older counts.** The next broadcast corrects it. Worth fixing with a version counter only if it shows up in practice.

## Review pass (Codex, after phase 2)

38. **Accepted:** test DB guard (`resetState` refuses unless the DB name ends in `_test`); JSON-only body parser and Origin check (login CSRF via HTML form); multipart disabled (temp files written before auth); `APP_KEY` must be at least 32 chars, the committed test key is refused in production, `.env.example` ships an empty key and the Docker image generates one; `trustProxy` trusts only the immediate peer (no X-Forwarded-For spoofing of the limiter key); framework 422 (JSON scalar body) mapped to `VALIDATION_ERROR` instead of 500.
39. **Partly accepted:** "Mongo can fail between the vote insert and `$inc`". This is the same window as a crash, now documented as such (entry 9). The fix is a recount job, not transactions.
40. **Rejected at first, fixed later (see 56):** "two overlapping first votes from a browser without a cookie get two identities". That is the inherent limit of anonymous cookie voting (clearing cookies does the same), and the UI can't trigger it: the poll page's `GET` issues the cookie before any vote is possible.

## E2E, Docker, CI

41. **Playwright has two modes: by default it builds and starts the API (production mode, port 3335, DB `livepoll_e2e`, random APP_KEY) plus `vite preview`; with `E2E_BASE_URL` it targets an already running stack (e.g. Docker on :8088).** · `pnpm test:e2e` works from a clean clone with only MongoDB running, and the same suite validates the Docker images. One worker: tests share a database and open several contexts each.
42. **The E2E suite was written by Codex CLI (as an independent worker) against a config written by me, then reviewed and re-run here.** It covers three browser contexts (live presence, results, close), double-vote protection, vote change, keyboard-only voting, axe WCAG 2 A/AA on open and closed polls, and the auth redirect.
43. **Docker: `node:22-alpine` multi-stage images, built from the repo root.** The API image ships only the compiled `build/` plus production deps (`pnpm deploy --prod --legacy`) and runs as `node`. The web image is nginx serving `dist/` and proxying `/api` + `/socket.io`. The API port is not published. · No BuildKit-only Dockerfile syntax (`COPY --chmod`, `# syntax=`), so it builds with the legacy builder too.
44. **`APP_KEY` in Docker is generated on first start by the entrypoint and stored in the `api-data` volume, unless provided via env.** · `docker compose up --build` works from a clean clone without committing any key. · A default key in compose (public = forgeable sessions).
45. **nginx sets the SPA's CSP (`default-src 'self'`; `style-src-attr 'unsafe-inline'` only for the bar widths) and overwrites `X-Forwarded-For` with `$remote_addr`.** Headers are set per static location because an `add_header` inside a location replaces server-level ones, and `/api` already sends its own.
46. **Cookies are `Secure` in production, including Docker on `http://localhost:8088`.** · Browsers treat `localhost` as a secure context, so it works locally. Reaching the stack via a LAN IP over plain HTTP needs HTTPS or `COOKIE_SECURE=false`.
47. **CI `pnpm audit --prod`: prints the full report, fails only on high/critical.** Known moderates (Nov 2026): three `@adonisjs/http-server` advisories (two open-redirect issues in `response.redirect()`/URL building, which this JSON API never uses, and one resource-consumption issue). All are fixed only in the Adonis v7 line, which the v6 requirement excludes. Accepted risk; upgrading to v7 is the fix.
48. **CI Docker job builds the images, runs `docker compose up --wait` and curls `/api/health` through nginx.** The full E2E-against-Docker run was verified locally (7/7 from a clean `down -v` + `build --no-cache`); in CI, E2E runs against the non-Docker stack to keep the pipeline fast.

## Review pass (fresh Claude reviewer + Codex, phase 6)

49. **Fixed: no reconnect after a graceful API restart.** `disconnectSockets(true)` on shutdown made clients see `io server disconnect`, after which socket.io-client never retries, so every open tab stayed "Connection lost" until reload. Now the server only closes the transports, and the middleware also calls `connect()` itself on `io server disconnect`.
50. **Fixed: a closed poll could flip back to open in the UI** when a REST response read before the close arrived after `poll:closed`. The poll slice treats `closed` as final.
51. **Fixed: join/leave race on the server.** `poll:join` awaits a MongoDB read before joining. A `leave` arriving in between was a no-op, so the join then landed and left a ghost viewer. The socket now remembers the slug it last asked for (`socket.data.wantedSlug`) and a stale join is dropped. A repeated join for the room the socket is already in is ignored (no presence re-broadcast spam). The ghost-viewer test fails on the old code (count 3 instead of 2).
52. **Fixed (a11y): closing and voting are now announced and keep focus.** The closed notice and "You voted for…" line sit in a `role="status"` region. After a vote (the form unmounts or remounts), focus moves to the confirmation; after a live close, focus moves to the closed notice if it was lost. Initial page load never moves focus.
53. **Fixed (small):** a 409 on vote refetches the poll (voted in another tab / poll just closed); the dashboard refetches on mount; switching polls while the socket is retrying no longer shows "connecting" over a real outage.
54. **Documented, not changed:** register answers `409 EMAIL_TAKEN`, which reveals that an email is registered. That is a deliberate UX trade-off (rate limited); the README no longer claims emails can't be enumerated. The results live region announces mostly the "N votes total" line, because the per-option text lives in `aria-label`s, which screen readers rarely re-read inside live regions. That is acceptable for a polite region on a busy poll; a throttled text summary would be the next step. A global "401 → logged out" handler for sessions ended in another tab is left out: authenticated calls then fail with a visible 401 error, and a reload re-checks `/me`.
55. **Kept, as interview talking points:** coalesced broadcasts, the CAS retry loop, the hand-rolled headers and Origin check, the APP_KEY bootstrap, and the `trustProxy` distance check. Each has a one-paragraph reason above.

## Review pass (Codex, whole repo, phase 6)

56. **Fixed: first-visit double vote.** The socket's `poll:state` could render the vote form before the first `GET` had issued the voter cookie. A vote then created cookie X, and the late `GET` response overwrote it with cookie Y, so the same tab could vote again (this disproves the reasoning in entry 40). The poll slice now has `myVoteKnown`: voting is enabled only after a REST response told us this voter's vote.
57. **Fixed: a join could miss a close.** The server read the snapshot before subscribing to the room, so a close broadcast between the two was lost. It now **joins first, then reads**; a stale join (the client left or asked for another poll) leaves again. The latest join intent is recorded before the "already in this room" shortcut, so A → B → A while B is loading ends in A.
58. **Fixed: graceful shutdown hung while WebSockets were open.** AdonisJS closes the HTTP server in a `terminating` hook, which waits for open connections, before provider `shutdown()` runs. Socket.io's transports are now closed in a `terminating` hook registered in `ready()`; hooks run in reverse order, so it runs first. Verified by hand: SIGTERM with a connected viewer exits immediately, and the client sees `transport close` with `active: true`, so it reconnects.
59. **Fixed: stale responses overriding newer state.** A `GET` started before a vote change can no longer restore the old `myVote` (per-request version check). A `/me` answer is ignored if a login, register or logout happened while it was in flight (an old 401 used to log out a user who had just logged in).
60. **Fixed: request validation reads the body only** (`validator.validate(request.body())`). `validateUsing` merges the query string, so credentials sent in a URL (and logged by proxies) were accepted.
61. **Fixed: email rules aligned.** VineJS now rejects UTF-8 local parts like zod does (`josé@example.com` could register via the API but not log in via the UI); added to the parity test.
62. **Fixed (ops):** `.env.*` files are excluded from the Docker build context and git (except `.env.example` and `.env.test`); `CORS_ORIGINS` can be set from the host for compose; nginx resolves `api` through Docker DNS at request time, so a recreated api container is picked up; Socket.io checks `Origin` in `allowRequest`, since its CORS setting only covers HTTP polling, not the WebSocket handshake.
63. **Fixed (small):** `/p/<not-a-slug>` (e.g. `/p/mine`) renders 404 without calling the API (it used to fetch `/api/polls/mine` and crash the reducer).
